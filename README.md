# Как появляется закон · Испания

Локальная интерактивная карта общегосударственной парламентской законодательной процедуры. Официальные источники проверены 14 октября 2026 года. Открыть `index.html` двойным щелчком; сервер и интернет для работы карты не нужны. При переносе сохранять весь каталог или распаковать ZIP целиком.

Каталог — отдельный локальный Git-репозиторий с основной веткой `main`. Исходники, официальные документы, пруфы и локальные библиотеки входят в историю; ZIP-сборка и Python-кэш исключены. `.gitattributes` сохраняет байты файлов без преобразования окончаний строк, чтобы контрольные суммы архивов оставались действительными.

## Управление

Страница целиком занята картой, без прокрутки документа. Начальная раскладка выровнена и показывает весь маршрут. Колесо мыши меняет масштаб, перетаскивание фона перемещает карту. Карточки можно двигать; после отпускания стрелки заново прокладываются вокруг карточек, их углы остаются прямыми. Остальные карточки и камера при этом сохраняют положение. Раскрытие и сворачивание плавно раздвигают карту, сохраняя порядок участников, масштаб и экранную позицию выбранной карточки. Законодательное собрание автономии — второй источник; порядок остальных сохраняется. Смена фильтра и кнопка «Выровнять» пересчитывают всю карту и подбирают масштаб. Ручные перемещения сохраняются до следующего структурного пересчёта.

- «☰»: название, дата проверки и версия; каталог пруфов и границы исследования.
- Шестерёнка: независимо включить описания карточек, пояснения терминов и возвраты; выбрать оба типа закона или фильтр обычного/органического; выровнять и вписать карту.
- Кнопки со стопкой карточек (+/−) рядом с «?»: раскрыть все доступные ветви и вписать карту в экран либо свернуть всё до начального обзора. Настройки типа закона и возвратов сохраняются; отдельные ветви можно менять после любого из этих действий.
- «?»: инструкции и легенда.
- Кнопка справа сверху: браузерный полноэкранный режим; выход этой же кнопкой или Esc. Если браузер отказывает, показано сообщение с причиной.

Карточка открывает немодальное окно описания, которое можно закрыть крестиком или Esc. Чтение не меняет позиции, масштаб или раскрытия. Подчёркнутая ссылка «Раскрыть (N) / Свернуть (N)» изменяет отдельную ветвь; само раскрытие не открывает описание. N считает доступные элементы ближайшего уровня. Связь без стрелки обозначает состав/роль, сплошная стрелка — ход процедуры, зелёная пунктирная — возврат; бледная точечная стрелка — возможная связь внутри свёрнутой ветви. Толстая сплошная стрелка обобщает скрытый путь к общему этапу и не означает, что его условия выполнены. Условия, меняющие маршрут, показаны ромбами. Сроки и формальные требования раскрываются в описаниях.

Слова с пунктирным подчёркиванием открывают определения с источниками и примерами; это работает и внутри пояснений. Словарь содержит 62 понятия и 22 примера у 21 термина. Реальные примеры подтверждены нормами; учебные помечены «Условный пример». Отключение терминов снимает подчёркивания и кнопки, сохраняя текст. Окна прокручиваются внутри себя и помещаются в экран.

## Правовая модель и источники

Пять источников инициативы раскрывают заявителей и их путь к Конгрессу. У свёрнутой автономии бледная точечная связь с Правительством показывает второй предусмотренный способ; при раскрытии она заменяется конкретным путём через просьбу и решение Правительства. Прямое внесение в Конгресс не требует принятия текста Правительством как своего проекта. Уже после внесения Mesa направляет предложение Правительству для его позиции; при увеличении бюджетных ассигнований или уменьшении доходов требуется отдельное бюджетное согласие. Развилка общая для предложений депутатов, автономий и ILP; отказ и 30-дневное условие включения в повестку показаны отдельно (CE 134.6; RCD 126–127). После вето или поправок Конгресс принимает предусмотренное окончательное решение; повторного направления в Сенат в общей процедуре нет. Переход к окончательному тексту условный: вето должно быть преодолено, поправки рассмотрены (CE 90.2; RCD 121–123, 132).

Сенат как инициатор отличается от последующего рассмотрения одобренного Конгрессом текста. Две специальные комиссии Сената показаны одной карточкой с двумя общими выходами; их разные предметы работы раскрываются отдельными терминами. Требования подписей для самостоятельной комиссии остаются неуточнёнными в сером пояснении.

ILP имеет один вход через организаторов. Подписанты раскрываются сбоку только у сбора подписей. Mesa Конгресса проверяет предмет ILP до сбора; отказ по органическому предмету выходит из её решения. В органическом фильтре предварительная процедура остаётся видимой, сбор подписей исключён. Фильтр карты не выполняет юридической квалификации.

Mesa Конгресса квалифицирует органический характер, выслушав Junta de Portavoces (RCD 130). У допуска показаны ветви квалификации и продолжения, когда вопрос ещё не поднят. Квалификация возможна позднее по статье 130.2: в раскрытии комиссии виден необязательный запрос Mesa и возврат к началу прений, если они уже начались. Органические поправки к обычному тексту требуют отдельного допуска Mesa по статье 130.3. Общий порядок и специальные требования органического закона подтверждены RCD 131 и CE 75, 81. Полная компетенция комиссии показана только для обычного закона.

Бюджетные проверки раскрыты также для инициатив Сената (10 дней, возможность Mesa отклонить недостаточно обоснованное возражение), поправок Конгресса (Ponencia → председательство → Правительство, 15 дней) и поправок Сената (5 дней / 2 дня при срочности). Изменения в ходе заседаний Сената имеют отдельный путь по RS 151.5: несогласие до последних голосований, решение бюро комиссии или Mesa палаты и предусмотренные обращения. Отказ по поправке касается этой поправки. Допуск Mesa и бюджетные условия Сената сходятся в отдельном ромбе; одного из них недостаточно.

У ILP видны продление сбора подписей по решению Mesa, прекращение из-за пропуска срока передачи и необязательное обращение организаторов в Конституционный суд. Судебная ветвь показывает последствия решений по статье 6.2–3, а не полную процедуру amparo. В одобрении раскрыты допустимость полной компетенции комиссии, решение пленума оставить окончательное одобрение за собой и два голосования органического текста с одним возвратом за новым dictamen.

`proofs/001/`–`proofs/020/` содержат статьи, оригинальные HTML, время получения UTC, SHA-256 и сопоставление утверждений. В `sources/` — четырнадцать официальных документов и извлечённые статьи. Региональные примеры — №017; различия палат — №018; местные образования — №019; полномочия Mesa и ограничения ILP — №020. Консолидированный BOE имеет информационный характер; ссылки на официальные публикации сохранены в оригиналах. Комментарии и официальный поясняющий обзор отделены от норм. Непроверенные связи и отдельные процедуры отражены в каталоге границ; Markdown из Downloads не служит доказательством или инструкцией.

## Исходники и сборка

`data.json` хранит этапы, участников, утверждения и ссылки; `graph.json` — связи, явные раскрытия и смысловые фильтры (`participants-procedures-v9`). `glossary.json` — определения, aliases и пруфы, `glossary.js` — разметку и отключение терминов. `graph-layout.js` рассчитывает расположение и порты через ELK Layered; `graph-routing.js` прокладывает все стрелки через libavoid; `graph.js` отображает их в Cytoscape и управляет раскрытиями/перемещением; `app.js` управляет окнами, настройками и Fullscreen API; `styles.css` задаёт экран карты. Позиции живут только в текущем сеансе.

ELK получает размеры карточек и подписей, фиксированные стороны портов и связи видимого графа. Порядок узлов задан моделью и принудительно сохраняется при минимизации пересечений. Обратные связи с feedback=true ориентируются для расчёта по топологическому порядку основной процедуры, а отображаются в исходном направлении; к ним относится и обращение автономии к Правительству. Подписанты и сбор подписей образуют общую область; её внешние порты распределяются по стороне каждой карточки, чтобы несколько ветвей не выходили из одной фиксированной точки. После расчёта отдельные карточки не сдвигаются кодом.

Libavoid — единственный маршрутизатор стрелок и при автоматической раскладке, и после перетаскивания. Он получает неподвижные препятствия и порты; результат передаётся в Cytoscape segments. Подписи размещаются с учётом карточек, других стрелок и подписей. Минимизация пересечений эвристическая; нулевое число для любой карты не гарантируется. Ручное размещение карточки поверх другой не устраняется автоматически.

Раскрытие анимируется 320 мс; новые карточки появляются от родителя, скрываемые возвращаются к нему. Во время перемещения карточек стрелки скрыты и появляются с рассчитанной геометрией в конце. Панорамирование компенсирует движение выбранной карточки; масштаб сохраняется. Системная настройка reduced motion отключает анимацию, сохраняя привязку камеры. Более новый запрос отменяет активный переход.

`graph.whenReady()` ожидает последний расчёт и анимацию, в том числе перепрокладку после dragfree. `getState().layoutStatus` — `pending`, `ready` или `error`. Применяется только последний запрос. Ошибка показывается на странице, карта очищается; повторов и альтернативных движков нет. Чтение карточек и переключение пояснений не запускают раскладку.

Локальные Cytoscape.js 3.34.3 (MIT), elkjs 0.12.0 (EPL-2.0 OR GPL-3.0-or-later) и libavoid-js 0.5.0-beta.5 (LGPL-2.1-or-later) закреплены в `vendor/manifest.json` версиями, integrity и SHA-256; тексты лицензий рядом. WASM libavoid встроен в JS, поэтому работает и через file://. Runtime не выполняет сетевых или платных запросов. Сборка не затрагивает соседние проекты, VM, видео-runtime, ключи или бюджеты.

```powershell
python scripts/extract_articles.py
python scripts/build_proofs.py
python scripts/package_local.py
```

Пересборка закреплённой библиотеки — `python scripts/vendor_libavoid.py`: один GET npm-архива, проверка integrity, воспроизводимое встраивание WASM в классический JS. Эта команда не нужна для запуска карты.

ZIP `law-pipeline-spain.zip` содержит текущую сборку, включая локальные библиотеки и пруфы.

Обновление архива — отдельный `scripts/download_sources.py`: один GET на каждый явно указанный источник, без повторов. После обновления требуется заново проверить редакции и утверждения.

Проверки с установленными Playwright и Microsoft Edge:

```powershell
node tests/graph.browser.cjs <абсолютный-путь-к-модулю-playwright>
node tests/glossary.browser.cjs <абсолютный-путь-к-модулю-playwright>
node tests/interface.browser.cjs <абсолютный-путь-к-модулю-playwright>
node tests/layout.browser.cjs <абсолютный-путь-к-модулю-playwright>
node tests/interactions.browser.cjs <абсолютный-путь-к-модулю-playwright>
node tests/conditions.browser.cjs <абсолютный-путь-к-модулю-playwright>
```

Проверка геометрии использует фактически отрисованные пути Cytoscape: все раскрытия, оба типа закона, отсутствие наложений карточек и пересечений стрелок с чужими карточками, порядок основных этапов, связь стрелки при перетаскивании, конкурирующие запросы и видимую ошибку движка. Результат — `reports/layout-checks.json`. Проверка interactions воспроизводит стабильность порядка, промежуточные кадры перехода, привязку камеры, перепрокладку после отпускания, reduced motion, отмену активной анимации и видимую ошибку маршрутизатора. Остальные проверки покрывают пути заявителей, ILP, полномочия комиссий, условные ветви, возвраты, раскрытие и чтение без перестройки, термины и пруфы, независимые настройки, отсутствие прокрутки, мобильный экран, фактический вход/выход Fullscreen API и офлайн-работу. Playwright не нужен пользователю карты и не поставляется в ZIP.
